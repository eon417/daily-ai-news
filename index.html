Why DuckDB 2.0 is faster: separate download pool for remote Parquet

●●●●● 5/5

MotherDuck explains a 2.4x speedup on a 2.2 GB, 228M-row Parquet file on S3: 7.7s in DuckDB 2.0 alpha versus 18.8s in 1.5.5. In 1.5.5, each worker alternated between downloading and decoding, so the network and CPU each sat idle at times. In 2.0, a separate download pool keeps dozens of row groups in flight while workers only decode, so both stay busy.

  • About 2.4x faster on a remote Parquet scan
  • Downloading and decoding now overlap
