Tailscale traced database corruption to a 16-year-old SQLite WAL-reset race

●●●●○ 4/5

Tailscale tracked silent data loss to a race between checkpointing and a write transaction: SQLite believed pages had been copied from the WAL to the main database when they had not, so committed writes vanished without error and left indexes pointing at missing pages. They found it with the tmstmpvfs VFS tracing shim; the fix is in SQLite 3.51.3, which adds a check for a WAL reset by another thread.

  • Bug present for at least 16 years; fixed in SQLite 3.51.3 — upgrade is the action item
  • Symptom: committed data invisible to later transactions, integrity_check failures, no error raised
  • Found using the tmstmpvfs VFS shim to trace checkpoint operations
  • Fix adds a checkpoint-time check for a WAL reset by another thread
  • 803 points / 146 comments on Hacker News

Chrome's partial IDCT scaling is why tiny JPEGs look wrong

●●●●○ 4/5

Chrome decodes heavily downscaled JPEGs with partial IDCT scaling — it skips high-frequency coefficients instead of decompressing fully, so fine detail disappears and images look thicker than in Firefox. The optimisation kicks in at scale factors near fractions with a denominator of 8, and at a 15px render size Chrome decoded at 1/8 scale, keeping only the constant component and dropping all edge softening and gradients.

  • Root cause traced through Skia and libjpeg-turbo: Chrome picks the closest denominator-8 fraction to decode at
  • Triggered by downscaling, not by file size — Firefox decompresses fully then scales, so it looks different
  • Author's conclusion: do not use JPEG for icons; the format's optimisations assume photographs
  • 256 points / 59 comments on Hacker News
