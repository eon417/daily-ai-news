Harnessing the universal geometry of embeddings

●●●●● 5/5

First method for translating text embeddings between vector spaces with no paired data and no access to the encoders. Translation goes through a universal latent representation, preserving semantic geometry across models differing in architecture and training data. The authors flag the security consequence directly: an adversary holding only embedding vectors can infer attributes of the underlying documents, undermining the assumption that vector databases are opaque.

  • Unsupervised cross-model embedding translation without paired data or encoder access
  • Relies on a conjectured universal semantic structure; high cosine similarity across diverse models
  • Enables classification and attribute-inference attacks against vector databases

WorldSculpt: generating compositional worlds from grounded videos

●●●●○ 4/5

WorldSculpt generates per-object meshes for cluttered scenes containing hundreds of densely occluded objects, taking multi-view video as input. It extends Pixal3D, a single-object 3D generative model, with multi-view conditioning that grounds generation in posed observations while retaining the prior's ability to complete unobserved geometry. It generalizes to large scenes without any scene-level training, and the authors release UE-MeshyScene, a photorealistic benchmark of 2,299 objects across six environments.

  • Anchor-aligned canonicalization + DINOv3 multi-view feature lifting, injected into a frozen prior via zero-init projections and LoRA
  • Finetuned purely on single objects yet handles severe scene occlusion via conditioning-view augmentation curriculum
  • Gains grow as scene complexity and occlusion increase; new UE-MeshyScene benchmark released

Making a Python interpreter in 1024 bytes

●●●●● 5/5

Austin Henley built a Python interpreter in 1024 bytes of C capable of running programs such as FizzBuzz. It uses a recursive descent parser that evaluates expressions directly during the parse, with no bytecode or intermediate representation. He started from a roughly 4,800-byte readable implementation and code-golfed it down to the size limit while keeping the essential language features working.

  • Control flow rides the C call stack; loops re-scan backward through source per iteration
  • State held in globals; single-character variable names index directly into a symbol array
  • Size reached via GNU C89 tricks: implicit int, ASCII literals, bitwise ops, param reuse as scratch

How to convert between wealth and income tax

●●●○○ 3/5

Graham offers a conversion rule: divide a wealth tax rate by the risk-free rate of return on capital to get the equivalent income tax rate. At an assumed 5% return, a 1% wealth tax is roughly equivalent to a 20% income tax increase — a ratio of about 20 to 1. He argues politicians describe wealth taxes as small precisely because they do not perform this conversion.

  • Conversion rule: wealth tax rate / rate of return on capital = equivalent income tax rate
  • 1% wealth tax maps to roughly a 20% income tax increase at 5% return
  • A median US state adopting it would reach ~61.75% marginal, above Denmark's 60.5%
